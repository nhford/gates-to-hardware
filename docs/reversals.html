Reversal analysis

What changes in the 45 total-gate reversals?

This breakdown matches the chart selection: preset Level 1, IBM New, CX backends, and Qiskit plus QUESO. Each row is one reversed circuit/backend/optimizer point; values are medians of five paired seeds.

What each column means
Circuit, backend, optimizer
The benchmark circuit, one of Manila/Lima/Jakarta, and the logical optimizer used.
Logical gates saved / Logical 2Q saved
Original logical circuit count minus the optimized candidate count, for all gates and two-qubit gates respectively. These values describe the logical optimizer before hardware compilation.
Compiled gates saved / Compiled 2Q saved
Preset-L1 compiled original count minus compiled optimized-candidate count, for all native gates and two-qubit gates. A negative value means the optimized candidate compiled to more gates—the reversal shown by the chart.
CX, RZ, SX, X, ID saved
Per-native-gate count in the compiled original minus the compiled optimized candidate. These counts show which IBM New basis gates account for the total change.
Depth saved / 2Q depth saved
Compiled original circuit depth minus optimized-candidate depth; 2Q depth counts layers containing two-qubit operations.
SWAPs saved
Inserted SWAP count in the compiled original minus the optimized candidate.
Duration saved
Estimated compiled duration of the original minus the optimized candidate, using backend gate durations; displayed in microseconds.
Fidelity gain
Calibration-based estimated fidelity of the optimized candidate minus the original, expressed in percentage points.

Every compiled metric is a median across matched seeds 0–4; the expandable rows show the individual paired-seed differences. Positive savings favor the optimized candidate.

When does logical gate reduction worsen time-to-99%?

This page checks every saved Qiskit / IBM New comparison compiled with preset Level 1 on the three CX backends: Manila, Lima, and Jakarta. A row is a reversal when logical optimization saves gates but increases the paired-seed median time to a 99% chance of at least one successful execution.

Time to 99% success probability (T99)
For per-execution estimated fidelity F, assume independent executions and count the runs needed for at least one successful execution with probability ≥ 99%:
N99 = ceil(log(0.01) / log(1 − F))   ·   T99 = N99 × estimated circuit duration
The table compares matched seeds and marks positive T99 changes as regressions. The fidelity is the calibration-derived circuit proxy saved in the benchmark, not measured hardware fidelity.
