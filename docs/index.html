Do logical savings survive hardware compilation?

How well do logical circuit metrics predict compiled cost and fidelity, and when do they mislead? This experiment compares VOQC, hardware-unaware Qiskit, and Quartz on 30 circuits from GuoQ’s Nam RZ benchmark suite.

Experimental setup

  1. Baseline. Compile the original Nam circuit directly for the target.
  2. Candidate. Optimize the same original circuit with VOQC, Qiskit level 3 without a backend, or Quartz’s bounded Nam rewrite search. Verify unitary equivalence, then compile with the same settings as the baseline.
  3. Hardware compilation. Use Qiskit level 1, SABRE, and matched seeds 0–4. Each target uses a fixed connected patch matching the circuit’s width. Compare the paired results before taking the median across seeds.

The original pilot uses nine five-qubit circuits, VOQC and Qiskit, Manila and Lima, and seed 0. It produced 34 verified comparisons.

How to read the chart

  • Logical savings. Original minus optimized gate count, two-qubit gate count, or depth in the common h/x/rz/cx basis.
  • Compiled savings. Baseline minus candidate native gate count, native two-qubit gate count, depth, estimated execution duration, or inserted SWAP count. SWAPs are counted before basis translation.
  • Fidelity gain. Candidate minus baseline in percentage points, using the product of calibrated gate fidelities on the mapped physical qubits. It is a proxy based on historical gate calibrations.

The chart reports Spearman rank correlation for the visible selection. A reversal is a point whose logical and compiled changes have opposite signs. Multiple observations share an input circuit, so the correlation is descriptive.

Aer fidelity check

In the five-qubit pilot, Qiskit Aer simulated the compiled operation using a backend-derived noise model. Average fidelity was evaluated against the ideal compiled unitary. Aer and the calibration proxy agreed on 14 of 16 optimizer rankings. On hlf_5, the proxy tied the optimizers on both targets while Aer favored VOQC.
