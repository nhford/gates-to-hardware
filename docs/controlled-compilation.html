Do reversals survive routing and translation alone?

On CX-native backends, we compare Qiskit Level 3 candidates with the originals using controlled compilation and preset Levels 0 and 1. The set includes IBM New reversals and qe_qft_4.

Controlled runs use calibration-free SabreLayout (20 random layout trials plus Qiskit’s topology layouts, 20 swap trials, four iterations; seeds 0–4), followed by native translation with no cleanup. Preset L0 and L1 use identity placement; that also disables L1’s calibration-aware VF2PostLayout. Calibration values are used only to score outputs.

How close is controlled compilation to preset L0? The saved data has 165 matched circuit/backend/seed cases (33 circuit/backend pairs × 5 seeds). All four structural metrics—native gate count, 2-qubit gate count, depth, and inserted SWAPs—match in 64/165 cases for both the original and optimized circuits. Across both paths, controlled-minus-L0 gate count has median −3 and ranges from −135 to 0; the median depth difference is −2 (range: −199 to +5). The controlled pipeline uses SABRE’s topology-aware placement and routing search, whereas preset L0 uses the supplied identity layout.

Compilation policy

The explicit pass sequence is SabreLayout → CountRoutingSwaps → BasisTranslator → GateDirection → BasisTranslator. SabreLayout jointly selects placement and inserts routing SWAPs. Basis translation decomposes unsupported instructions, including routing SWAPs. The pipeline does not run a general optimization loop.

This experiment measures routing and translation after logical optimization. Remaining gate sequences may contain redundancies that preset Level 1 would simplify. SABRE selects among candidates using its routing cost; total native gate count is an evaluation metric.
